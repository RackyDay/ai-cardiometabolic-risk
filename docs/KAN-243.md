# KAN-243: MedlinePlus educational content

## Source and request flow

Verified against the [official MedlinePlus Web Service documentation](https://medlineplus.gov/about/developers/webservices/).
The documented keyword endpoint is `https://wsearch.nlm.nih.gov/ws/query`.
Requests use `db=healthTopics`, `term=<query>`, `retmax=<limit>`, and `rettype=brief`.
Responses are XML (`nlmSearchResult`, `count`, `list/document`, and named `content` elements), including HTML in summaries and titles.

A live request with an Origin header returned no `Access-Control-Allow-Origin` header, so browser fetches cannot read the upstream response directly.
The existing FastAPI app therefore provides a public adapter:

1. Learn's view model reads general `searchTerms` from `learnRiskFactors.js`.
2. `searchMedlinePlus` calls our `GET /learn?query=...&limit=...` route using the existing `VITE_API_URL` setting (default `http://localhost:8000`).
3. FastAPI URL-encodes the upstream request with httpx, parses the XML, strips markup, checks links, and returns JSON `{query, articles}`.
4. React renders plain text and MedlinePlus links through `ArticleCard`, with source attribution. No upstream HTML is inserted into the DOM.

No account, API key, assessment values, or authentication headers are needed. Existing FastAPI CORS settings still apply to the frontend-to-backend request.

## Reusable frontend interface

```js
import { searchMedlinePlus } from "./services/medlinePlusApi";

const controller = new AbortController();
const articles = await searchMedlinePlus("blood pressure", {
  limit: 3,
  signal: controller.signal,
});
// controller.abort() cancels a superseded search.
```

- `query`: string, whitespace normalized, maximum 200 characters; blank searches return `[]` without making a request.
- `limit`: integer from 1 to 5, default 3.
- `signal`: optional AbortSignal. Caller cancellation rejects with `AbortError`; other failures reject with an Error carrying a displayable message.
- Result: `Array<{id, title, summary, url, source}>`. All fields are strings, `source` is `MedlinePlus`, and `id` is the canonical topic URL supplied by the service. Summaries are plain text, shortened to about 320 characters. No matches return `[]`.

KAN-245 can import this service, manage its own search/loading/error state, and cancel superseded requests. It does not need to change the risk-factor configuration or Learn's general-topic loader. No search UI or assessment-based selection is included here.

## Page behavior and upstream limits

Each distinct configured term is searched once per page load, with three concurrent requests at most. Terms are searched separately because joining multiword terms with word-level `OR` broadened live results excessively. The page takes one result per term, deduplicates by URL within each factor, and shows at most two articles per factor.

Static educational descriptions remain visible during loading, empty results, and failures. Cards have distinct loading, no-results, unavailable, and partially available states. A secondary Reload articles control appears beside the status message only when article fetching fails; it reloads topics after pending requests have settled. Leaving Learn aborts its browser requests. The assessment placeholder remains reserved for KAN-244.

FastAPI caches successful results, including empty results, for 12 hours with a 256-entry bound. Identical in-flight requests are shared. It allows at most three upstream requests simultaneously and 80 per minute, below the documented 85-per-minute limit. Upstream timeouts return 504, HTTP/transport/malformed-response failures return 502, and local throttling returns 503 with `Retry-After: 60`. The frontend also has a 15-second timeout.

The cache and limiter are per process, matching the current single-worker development setup. A deployment with multiple workers/instances sharing one public IP needs a shared cache/limiter to enforce the upstream quota across them.

## Manual testing

From the project root, use two terminals with the existing dependencies and environment configured:

```powershell
cd backend
py -m uvicorn main:app --reload
```

```powershell
cd frontend
npm run dev
```

1. Open `http://localhost:5173/learn` as a guest. All 15 schema factors should retain their descriptions and show up to two MedlinePlus articles each, or an explicit no-results state. There should be no search bar or personalised article selection.
2. Open an article and check its MedlinePlus destination, readable summary, and source attribution. Test keyboard focus and narrow mobile widths, plus enlarged text.
3. Use browser network throttling and reload to see loading states. Navigate away while loading, then return; the page should recover without React warnings.
4. Sign in using an existing test account and revisit Learn. General content should work in the same way, without altering the dashboard, current assessment, or history. Empty/null optional assessment fields should have no effect on these general queries.
5. Inspect `GET http://localhost:8000/learn?query=cholesterol&limit=2`: expect JSON with a query and articles. `/learn?query=` returns an empty array; `limit=0` or `limit=6` returns 422.

## Failure and no-results testing

- In Chrome DevTools, enable Network request blocking for `*localhost:8000/learn?*` (adapt the host/port to `VITE_API_URL`) and reload Learn. Overviews must remain readable, cards show unavailable messages, and Reload articles appears. Unblock requests and click Reload articles to recover.
- Blocking the local adapter is reliable even with warm backend caches. Simply disconnecting the upstream service can leave previously cached successful topics available for 12 hours.
- Test genuine no-results behavior with an unlikely query, for example `/learn?query=zzzxqvnonexistenttopiczz&limit=2`. No matching topics returns 200 with `articles: []`; service availability can still produce a normal API error.
- Automated tests below simulate upstream HTTP failures, timeouts, malformed XML/JSON, unsafe links, no matches, throttling, cancellations, partial failures, and retry recovery without contacting external services.
